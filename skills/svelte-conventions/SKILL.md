# Svelte / Tailwind conventions

- **Svelte 5 runes** (`$state`, `$derived`, `$props`, `$effect`) — never `export let` or the
  legacy store-in-component patterns.
- **Styling is token utilities only.** Design tokens live in the CSS entry configured in
  `components.json` and map into Tailwind v4 `@theme inline`. Use the semantic shadcn tokens:
  `bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`,
  `bg-primary`/`text-primary-foreground`, `bg-card`, plus whatever brand tokens the project
  defines. Prefer these over Tailwind's default color palette. Radii use the `--radius`-derived
  scale (`rounded-lg`, `rounded-2xl`, `rounded-3xl`).
- **Dark mode** is class-based (`.dark`, via `@custom-variant dark`). Define both light and
  `.dark` token values in the CSS entry; generated shadcn components carry their own `dark:`
  variants.
- **Mobile-first.** Author base styles for the smallest viewport and layer wider layouts with
  `sm:`/`md:`/`lg:`. Touch targets ≥44px; primary actions within thumb reach; respect safe areas
  (`env(safe-area-inset-*)`).
- `src/lib/components/ui/**` is generated by the **shadcn-svelte** CLI — add or regenerate
  components via the CLI, don't hand-edit them. App-specific components live in
  `src/lib/components/*.svelte`.
- Project-level instructions (`CLAUDE.md`, `AGENTS.md`) override anything here.
